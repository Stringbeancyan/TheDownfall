# Breakwater: first playable candidate

**Build target:** UE 5.6, four cooperative players on a dedicated server. The
candidate is authored source; it has not yet been compiled or played in Unreal.
Its 180 m square map is generated by `Scripts/build_vertical_slice.py`.

## Scene layout and loop

Coordinates below use centimeters, X east-west on the scene plan and Z up. The
solar model independently calls world +X north; rotate the art-world alignment
before adopting geographic coordinates in production. This blockout is near
the origin and is not georeferenced.

| Element | Placement | Purpose |
|---|---|---|
| Squad insertion | X −4,600/−4,900; Y ±200; Z 120 | Four separate player starts on western approach |
| Main roads | Crossing at origin; width 1,400 | Visible movement/vehicle lanes with 720 cm sidewalks |
| Ferry Exchange | −3,900, −3,900 | First interior, two door openings, cover and lighting |
| Grid Service | 3,900, −3,900 | Vehicle/workshop production destination |
| Tide Market | −3,900, 3,900 | Alternate indoor traversal route |
| Relay Annex | 3,900, 3,900 | Objective-adjacent interior |
| Service car | −1,600, −420, 65 | One-seat entry/drive/exit prototype |
| Sentinel R3 | 2,700, 600, 110; yaw 180 | One patrolling enemy, initially facing approach |
| Relay | 1,800, 2,000, 0 | 11 × 11 m capture region; hold for 15 seconds |
| Four barriers | Along the approach and relay corner | Damage/cover/collision and late-join reconstruction checks |
| District bounds | ±9,000 cm | Explicit finite slice boundary |

Each building is 44 × 36 m with a 6.8 m ceiling, ground floor and roof, two
2.6 m-wide / 3.3 m-high openings, an internal partition and worktops. Upper
floors, elevators, finished doors, functional furniture and production interiors
are not implemented. The simple robot does not navigate a room graph; keep its
initial patrol in the open lane during acceptance.

The gameplay loop is approach → optional vehicle test → use barrier cover →
eliminate the Sentinel → enter/hold the relay → observe `RELAY ONLINE`. Capture
is proximity-based, can occur without killing the robot, and does not yet end
the match. Defeated players respawn after five seconds. There is no inventory,
carryable routing key, extraction trigger, revive interaction or checkpoint
service in this first code drop; those belong to the full Last Light mission.

Initial environment is 02:00 solar time and rain state. A game day takes 1,800
real seconds. Every 120 real seconds the server advances a scripted
rain → storm → fog → clear → rain cycle, blending for 35 seconds. Directional
lights, skylight, fog and tagged lamps react. Rain particles, wind-blown cloth,
animated water and wetness material assets remain production work.

## Native first cinematic: Last Light rehearsal

`ADownfallCinematicDirector` is placed at the origin. Press F8 in a standalone
client. It plays locally for 12 seconds; F9 skips. It uses temporary cameras and
subtitles, leaves the live server running, and returns to the current pawn with
a 0.65-second blend. It does not acquire movement/input locks. No camera is
replicated and watching the rehearsal does not grant immunity.

| Time | Camera movement / look target | Subtitle |
|---|---|---|
| 0–4 s | (−4,200, −1,900, 500) to (−3,000, −1,500, 360), look (1,000, 300, 150), horizontal FOV 65° | Mira: “Wait. That light was on a second ago.” |
| 4–8 s | (−1,700, −450, 165) to (−1,450, −300, 155), look (−500, 250, 160), FOV 48° | Orin: “Mira. Behind the car. Now.” |
| 8–12 s | (1,700, −400, 190) to (2,200, −150, 160), look (2,700, 600, 120), FOV 38° | Mira: “I see it. Keep your head down.” |

This rehearses camera placement, text timing and return to gameplay. It contains
no speaking character, voice, lip sync, cinematic sound, mocap or Sequencer asset.

## Production first cinematic: Last Light, 60 seconds

**PLANNED asset:** `LS_DF_LastLight` in `/Game/Downfall/Cinematics/LastLight/Sequences`.
Location: western relay approach, 02:00, rising coastal rain, moderate wind.
Characters: Mira, a rescue-systems engineer, and Orin, a port electrician;
background: two responders helping civilians under the market canopy. A remote
Sentinel should be physically present before the reveal, not spawned by a cut.

**Lighting:** blue-gray atmospheric fill; warm service-car hazards, low clinic
emergency practicals and muted cyan route signs. Meter skin exposure against the
rain-black road. Headlight glare remains motivated and restrained. Final exposure
must match gameplay; no cinematics-only light that disappears on the handoff.

**Performance capture handoff:** synchronized body, facial cameras and clean
audio; bind finger/prop contacts; gaze targets named per shot; lip/jaw/teeth/tongue
review at final camera distance; remove sliding feet; record overlaps as isolated
stems plus a shared table read. Deliver original 48 kHz dialogue, timecode,
pronunciation sheet, emotional beats and localization-safe subtitle cues.

**Sequencer assembly:** create one Level Sequence with seven subsequences;
possessable actor bindings for Mira/Orin/vehicle/robot; CineCameraActors with
explicit sensor/lens/focus tracks; body animation and Control Rig cleanup tracks;
facial curves with gaze layer; dialogue/subtitle events from a single cue sheet;
weather uses the existing World Director rather than a second clock. Completion
restores camera state. A mission controller later owns any encounter activation;
an individual skipping the film must not advance server objectives.

**Multiplayer cutscene policy:** the native rehearsal is optional. Production
combat-adjacent scenes retain server movement/combat and provide a non-cinematic
dialogue alternative. Any future staged cooperative sequence needs explicit
server start time, participant opt-in, abort/death/disconnect/late-join behavior,
and testing for spectators. A paused client never pauses the server.

## Precise Blueprint integration recipes

The following assets are **PLANNED authoring tasks**, using native APIs already
defined. They are not checked-in `.uasset` graphs.

**`BP_DF_Responder`** derives from `ADownfallCharacter`. `Event BeginPlay` →
`GetCombatComponent` → `Bind Event to OnShot`. The bound event receives
`MuzzleLocation`, `Direction`, `WeaponId`; select Kestrel/Vesper presentation data
by ID → spawn capped Niagara muzzle effect → `Get World Subsystem
(DownfallAudioSubsystem)` → `PlaySpatialEvent` with supplied mono `USoundBase` and
location. Do not call damage or modify ammunition in this graph. Assign the pawn
class in a derived GameMode once its assets are validated.

**`BP_DF_ImpactProjectile`** derives from `ADownfallProjectile`. Override
`OnImpactPresentation(Position, Normal)` → look up an authored impact profile →
align decal/FX to Normal → request spatial impact sound. Assign this class to the
character combat component's `ProjectileClass`. Surface typing needs an expanded
replicated impact payload before selecting material-specific remote-client FX.

**World materials:** create `MPC_DF_Environment` with `RainIntensity`, `Wetness`,
`SnowCoverage`, `WindSpeed`, `TimeOfDayHours`; assign to World Director. Material
collection scalar `Wetness` × mesh exposure mask → clamp 0–1 → dry/wet roughness
lerp. Use art pipeline graphs for physically plausible values. Weather volumes
and clothing exposure must be added before rain affects sheltered interiors.

**Acoustic authoring:** place `ADownfallAcousticZone` inside each room; size Bounds
to interior space, choose Environment and Priority, assign a real reverb submix
with an effect chain and its send level. `PlaySpatialEvent` queries the listener's
zone once, computes delay/occlusion and plays the supplied sound. Ongoing portal
updates, early reflections and transmission are future acoustics systems.

**UI upgrade:** derive CommonUI screens later and subscribe to health delegates,
combat getters and objective state. Prototype HUD is native Canvas, not CommonUI.
Keep server-owned values read-only in widgets; remapping updates local Enhanced
Input contexts. Provide input method glyphs, subtitle options and focus restoration.

## First art replacement gate

Replace one street bay, one relay room, Mira, the Kestrel C6 and the Vela service
car as a coherent set. Required deliverables are in the asset manifest: model,
UVs, PBR textures, collisions, rig/animations where applicable, LODs, damage and
import metadata. Compare the same 02:00 view in dry, rain and storm states, then
profile a firefight from that camera. Record measured image quality, GPU time,
memory, network cost and audio intelligibility together. No claim of AAA visual
quality is made until those assets and captures exist.
